This guide helps you plan and execute a migration from Courier to Notify. It covers how the two platforms compare, what changes when moving to Notify, and a step-by-step approach for migrating your notification workflows, templates, providers, and user data.

## Why Notify?

- **Unified Workflows:** Courier separates "Templates" (content) and "Automations" (logic). Notify unifies routing, timing (delays/digests), and content into a single **Workflow**, making it much easier to manage the entire lifecycle of a message.
- **Choose How You Build:**
  - **Visual Builder:** A powerful drag-and-drop dashboard for teams that want a no-code UI to design content and orchestration.
  - **Notify Framework:** An optional code-first approach that lets developers write workflows in TypeScript, version-control them, and test them locally.
- **Unrivaled React Ecosystem:** Notify's in-app Inbox comes with pre-built React components for a drop-in experience, plus powerful headless hooks if you want to build a completely bespoke UI.
- **Data Sovereignty:** Because Notify is open-source, you can use our fully managed Cloud platform or self-host it on your own infrastructure to meet strict compliance requirements.
- **Translations:** Notify supports translations for your notifications, making it easier to localize your notifications for your users. Use translation keys in channel step editor to localize your notifications and Notify will send the notifications in the subscriber's locale. Read more on how to [use translations](/platform/workflow/advanced-features/translations) in the Notify Dashboard.
- **Multi-tenancy:** Send notifications to different tenants or organizations within the same Notify project and let users manage their notification preferences for each tenant. Read more on how to [use multitenancy](/platform/workflow/advanced-features/contexts) in the Notify Dashboard.

## Mapping Courier concepts to Notify concepts

Before you dive into the migration steps, here is a quick cheat sheet for translating your Courier setup into Notify's terminology.

| Courier Concept | Notify Equivalent | How they compare |
| --- | --- | --- |
| **Automations + Templates** | **Workflows** | Notify combines your message content and delivery logic (like delays or digests) into a single, easy-to-manage Workflow. |
| **Profiles / Users** | **Subscribers** | The core entity receiving the notification. Just like Courier, Notify allows you to pass user data inline, meaning you don't have to sync users beforehand. |
| **Lists / Audiences** | **Topics** | Used for broadcasting. In Notify, you trigger a workflow to a Topic, and Notify automatically fans it out to all subscribed users. |
| **Preferences** | **Preferences** | Notify categorizes user opt-in/opt-out states natively by Workflow or via global channel settings. End user can manage their preference for each workflow or globally. |
| **Integrations** | **Integrations** | Both platforms connect to external providers (Twilio, SendGrid, etc.). Notify lets you define multiple active integrations for each channel provider and set a primary integration per environment. |
| **Inbox** | **Inbox** | Notify's in-app Inbox comes with pre-built React components for a drop-in experience, plus powerful headless hooks, javascript and react native support if you want to build custom Inbox UI. |
| **Tenants** | **Context** | Notify supports multitenancy out of the box, the most simple way to implement tenant separation sending context information while triggering a workflow. Notify will automatically filter the notifications for the tenant and the end user will see only the notifications relevant to their tenant. |

## Migration steps

We recommend a phased approach to migrate safely without dropping any messages.

<Steps>
  <Step title="Phase 1: Set up your workspace and providers">
    1. **Create your workspace:** Sign up for [Notify Cloud](https://dashboard.novu.co/auth/signup). You'll automatically get isolated **Development** and **Production** environments.
    2. **Connect your providers:** In the Notify Dashboard, navigate to the **Integrations Store**. Reconnect the ESPs (SendGrid, Postmark), SMS gateways (Twilio), and Push providers (FCM, APNS) you were using in Courier.
  </Step>

  <Step title="Phase 2: Migrate audience data">
    You need to sync your Courier `Profiles` to Notify `Subscribers`. The easiest way to handle this is a **Lazy Migration**:

    Instead of exporting and importing thousands of users manually, simply update your backend to pass the user's details (email, phone, name) inline when you trigger a notification. Notify will automatically create or update the Subscriber on the fly.

    *If you prefer to sync ahead of time, you can easily script it:*

  <Step title="Phase 3: Translate automations to workflows">
    In Courier, you link Automations to Templates. In Notify, you recreate these as **Workflows**. You have two great options for building them:

    <Tabs>
      <Tab title="Dashboard">

    **Option A: The Dashboard Visual Builder**
    If your product or marketing team loves managing notifications visually, they will feel right at home in the Notify Dashboard. You can drag and drop Email, SMS, and In-App steps, add Delays and Digests, and edit message content directly in the browser. Read more on how to [manage workflows](/platform/workflow/overview) in the Notify Dashboard.

      </Tab>
      <Tab title="Code-first">

    **Option B: Code-First with Notify Framework**
    If your engineering team wants more control, you can use `@notify/framework` to define the same workflows directly in your codebase using TypeScript. 

    *A simple code-first example:*

    ```typescript

    export const weeklyDigestWorkflow = workflow('weekly-digest', async ({ step }) => {
      // Replaces Courier's digest node
      const digestResult = await step.digest('batch-events', () => ({ amount: 7, unit: 'days' }));

      // Replaces Courier's send node + template
      await step.email('send-summary', async (controls) => {
        return {
          subject: `Your Weekly Activity Summary`,
          body: `You have ${digestResult.events.length} new updates this week.`,
        };
      });
    });
   
    ```

      </Tab>
    </Tabs>
  </Step>

  <Step title="Phase 4: Swap out the in-app Inbox">
    If your app uses Courier's Inbox component, swapping it for Notify's is incredibly simple. Notify's Inbox provides out-of-the-box real-time updates and unread counts.

    ```bash
    npm install @notify/react
    ```

    ```tsx

    export default function NotificationCenter() {
      return (
        <Inbox
          applicationIdentifier="YOUR_NOVU_APP_ID"
          subscriberId="usr_123"
          // We recommend using HMAC encryption in production for security
          subscriberHash="HMAC_HASH_GENERATED_ON_BACKEND" 
        />
      );
    }
    ```
  </Step>

## API endpoint quick reference

Need to update your backend API requests? Use this mapping to find the Notify equivalent of your Courier endpoints.

| Action | Courier Endpoint | Notify Equivalent |
| --- | --- | --- |
| **Trigger a Message** | `POST /send` | [`POST /v1/events/trigger`](/api-reference/events/trigger-event) |
| **Send to Many** | `POST /bulk` | [`POST /v1/events/trigger/bulk`](/api-reference/events/bulk-trigger-event) |
| **Update User** | `PUT /profiles/:id` | [`PUT /v2/subscribers/:subscriberId`](/api-reference/subscribers/update-a-subscriber) |
| **Fetch User Data** | `GET /profiles/:id` | [`GET /v2/subscribers/:subscriberId`](/api-reference/subscribers/retrieve-a-subscriber) |
| **Modify Opt-Ins** | `PUT /users/:id/preferences/:topic` | [`PATCH /v2/subscribers/:subscriberId/preferences`](/api-reference/subscribers/update-subscriber-preferences) |
| **Manage Lists/Groups** | `PUT /lists/:id` | [`POST /v2/topics`](/api-reference/topics/create-a-topic) |
| **View Logs** | `GET /messages` | [`GET /v1/notifications`](/api-reference/notifications/list-all-events) |
